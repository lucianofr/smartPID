## Config deviations (and why)

1. **`tsconfig.node.json`: removed `"noEmit": true`.**
   The brief's literal config fails the build with `error TS6310: Referenced project '.../tsconfig.node.json' may not disable emit`. A `composite: true` project referenced under `tsc -b` (as the brief's `build` script `tsc -b && vite build` invokes) is part of the build graph and must be allowed to emit its `.tsbuildinfo`. This is a genuine config bug in the brief. Fix matches the official Vite `react-ts` template, which does not place `noEmit` in `tsconfig.node.json`. Verified with TypeScript 5.9.3 (installed under `^5.5.4`). After removal, `npm run build` passes. The app's real `tsconfig.json` still has `noEmit: true`, and Vite consumes app source directly, so no stray `.js` is produced from `src/`.

2. **`packages/smart_pid_web/.gitignore`: appended `*.tsbuildinfo`, `*.config.js`, `*.config.d.ts`.**
   Consequence of deviation #1: with `tsc -b` now emitting, the composite build writes `vite.config.js`/`.d.ts`, `vitest.config.js`/`.d.ts`, `playwright.config.js`/`.d.ts`, and `tsconfig.*.tsbuildinfo` into the package root. These are build artifacts, not source, and must not be committed. Added matching ignore patterns and confirmed regenerated artifacts stay untracked after a fresh `npm run build`.

3. **`vitest.config.ts`: added `passWithNoTests: true`** — explicitly required by the task decisions so the 0-test toolchain-health check (Step 10) exits 0 instead of vitest's default non-zero "No test files found".
