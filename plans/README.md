## Key findings behind plan 001 (evidence at commit b7fbcc3)

1. **Silent training failure → random policy drives Ti** — `rl_engine.py:
   524-556`: sb3 `model.train()` is called without `set_logger()`, which
   raises `AttributeError` (verified against sb3 source, `common/base_class.py`);
   the exception is swallowed at DEBUG, but `_init_sb3_model()` has already
   set `self._model`, so `compute_gamma` (line 450) switches from the sane
   fallback heuristic to an untrained random SAC network. No quality gate
   exists before the neural policy acts. **Fixed**: `set_logger()` call
   added; `_policy_ready()` gate requires 3 successful trains.
2. **Reward is an aliased point sample** — reward uses one instantaneous
   (error, delta_error, co) sample per AI period (3×TSS s) while windowed
   KPIs (IAE, osc, TV) already arrive in `ai_worker.py:439-455`
   (`self._latest_stats`) and are used by the Fuzzy path but never by RL.
   **Fixed**: `compute_reward_from_stats()` added and wired in.
3. **Cross-loop shared state** — `compute_reward_surge_level` stores
   `_prev_delta_co` on the module-level function object (`rl_engine.py:167-172`),
   shared across all controllers and worker threads. **Fixed**: moved to a
   per-`RLEngine`-instance attribute; regression test added.
4. **Non-Markov observation** — obs `[error, delta_error, co, integral_val]`
   omits the current Ti/Ki being actuated (`rl_engine.py:343-360`).
   **Fixed**: 5th `ti_norm` dimension added (log-scale position in
   `[limit_min, limit_max]`).
5. **Invalid + dead PPO path** — `_train_ppo` fills an on-policy buffer with
   off-policy data and `log_prob=0.0`; `AIWorker` hardcodes SAC anyway.
   **Fixed**: deleted; unsupported algorithms coerce to SAC with a warning.
6. **`rl_learning_rate` config ignored** — hardcoded `3e-4` at
   `rl_engine.py:647`; `AIConfig.rl_learning_rate` exists but is never wired.
   **Fixed**: threaded through the constructor and `ai_worker._create_engine`.
7. **sb3 not installed in practice** — optional `ai` extra
   (`packages/smart_pid_core/pyproject.toml:40-43`), absent from the default
   `uv sync --all-packages` venv, so production "RL" today is the fallback
   P+D heuristic. **Unchanged by design** — stays optional; E2E Part A
   validates the fallback path explicitly for this reason.
8. **Disk churn** — full RL state (JSON replay buffer + model zip) written
   after every AI cycle (`ai_worker.py:316-317`). **Fixed**: throttled to
   every 10th cycle; `stop()` still saves unconditionally.

## Findings considered and rejected

- **Auto-revert / model-vs-fallback reward comparison framework**: deferred —
  the train-count gate plus the Sv bound and limit clamps are a sufficient
  safety envelope for now; a full eval harness is not justified before field
  data exists. (Noted in plan 001 maintenance notes.)
- **Retuning reward weights via simulator sweeps**: deferred — needs the
  stats-based reward landed first; weights are marked as tunable constants.
- **Installing sb3 by default**: rejected — torch is heavy; the `ai` extra
  stays optional and the fallback heuristic remains the no-sb3 behavior.
