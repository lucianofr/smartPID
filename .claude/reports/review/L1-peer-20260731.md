### Verified non-issues (from the assignment's specific questions)

- `_resync_simulator_link` runs after `await self._repo.reopen(...)` in all three entry points (`new_project:130`, `open_project:149`, `import_project:181`), and `SQLiteRepository.reopen()` mutates `self._db_path`/`self.engine` in place on the same object (`sqlite_repo.py:843-856`), so `self._repo.list_all()` inside `_resync_simulator_link` (line 318) queries the **new** project's controllers, not the old one's.
- `self._opcua_adapter.start()` is idempotent: `OPCUAAdapter.start()` (`opcua_adapter.py:67-69`) returns immediately if its thread is already alive, so calling it a second time in `_resync_simulator_link` (after `_load_opcua_endpoint` may already have started it) is safe.
- `bind_opcua_client`'s `nodes.get("pv", "")` when `opcua_node_ids()` returns `{}` is guarded (`if not nodes: continue`, line 106) so a not-yet-created controller is skipped entirely, not registered with empty strings. A genuinely partial dict never occurs in practice: `OPCUAServer._async_register_controller` builds `node_ids` from a `nodes` dict populated with all keys atomically before assignment (`opcua_server.py:199-258`). Downstream, `OPCUAAdapter._async_read_telemetry` already skips empty node ids (`if nid:`, `opcua_adapter.py`), so an empty string is safe there; `write_output`/`write_co` do not guard against an empty node id, but that is pre-existing, unrelated to this diff, and unreachable given the above.
- `monitor_worker.py`'s `tick_start = time.monotonic()` move into the inner `try` (line 82) does not lose accounting: it is still the first statement in the loop body, `elapsed`/`sleep_time` are computed correctly on the success path, and the exception path waits the full `self._scan_rate_s` (matching `stats_worker`/`pid_worker`'s existing paced-retry convention, not a partial-elapsed calculation).
- `main.py:438`'s switch from unconditional per-id registration to `bind_opcua_client`'s "skip empty nodes" behavior does not change boot behavior: `simulator_adapter.start_opcua()` (line ~423, before the binding call) blocks on `OPCUAServer._ready` until every pre-registered controller's nodes are created (`opcua_server.py:71-83,172-173`), so `controller_node_ids` is always fully populated by the time `bind_opcua_client` runs at boot.
