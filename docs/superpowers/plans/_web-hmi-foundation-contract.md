## 1. Product decision overrides (apply to ALL plans)

- **Mono-user / NO RBAC.** Single admin login. There is **no user CRUD**, **no
  role-based UI gating**, and **no `routers/users`** in the target system (TD-007
  removes it). Auth is still **mandatory on every endpoint** via a single
  dependency `require_authenticated_admin`. Where the umbrella or the Fatia 7 spec
  mention RBAC / `require_operator|supervisor|admin` / user management, the plan
  MUST substitute the single-admin model. Credential boundary preserved: admin
  credentials live in `users.db`, never inside `.spid` projects.
- **Backend security fixes are already applied** (branch `fix/backend-security-hardening`):
  auth on all `routers/project.py` routes, path-traversal sanitization
  (`_safe_project_path`), `/commands/tuning` clamp + supervisor→admin guardrail
  (`TuningCommand`), `.spid` upload cap → HTTP 413 (`max_upload_bytes`, 50 MB),
  `python-multipart` declared. Plans assume these exist; they do NOT re-implement them.
- **Optimization enable toggle already exists** (branch `feat/pid-optimization-enable-toggle`):
  `Controller.optimization_enabled`, `POST /commands/optimization {controller_id, enabled}`,
  `AIWorker.set_enabled()`, sqlite migration. This is the **AI-optimization** enable,
  distinct from any "PID enable" (see GAP register §8).

## 2. Frontend stack (locked)

- React 18 + Vite 5 + TypeScript 5 (strict).
- **Server state:** TanStack Query v5.
- **Realtime:** native `WebSocket` wrapped by the `useRealtime` hook (§5).
- **Charts:** **uPlot** (sliding window, decimation, ≤16 ms/frame budget).
- **Tests:** Vitest + @testing-library/react (unit/hook/component); Playwright (e2e).
- **API typing:** `openapi-typescript` generates types from the FastAPI `/openapi.json`.
- **No Tauri/Electron** — browser only; user opens `localhost`.

## 4. WebSocket envelope — `src/realtime/envelope.ts` (CANONICAL, Fatia 0+1)

```ts
export type RealtimeType = 'status' | 'action' | 'alarm' | 'ai' | 'stats';

export interface RealtimeEnvelope<T = unknown> {
  type: RealtimeType;
  loop_id: number | null;   // null for global events (EVENT.SYSTEM)
  seq: number;              // per-connection sequence, for gap detection
  ts: number;               // epoch seconds, server time
  data: T;
}

// Live dashboard frame = STATUS.{id} (published by pid_worker.py:457 / monitor_worker.py:84).
// Real wire payload (msgpack dict) per backend map §9 — these are the AUTHORITATIVE fields:
export interface StatusData {
  pv: number; sp: number; co: number;
  bkcal_in: number; bkcal_out: number;
  mode: string;            // ControllerMode value (8 modes + BYPASS)
  kp: number; ti: number; td: number;
  integral_val: number;
  timestamp: number;
}
// Derived client-side (NOT on the wire): error = sp - pv; saturated from co vs CO limits.
// OPC connection state comes from REST poll GET /opcua/status, NOT from STATUS frames.
export interface ActionData { cv: number; delta: number; }          // ACTION.CTRL.{id} (pid_worker.py:432)
// GAP-3b (verified in Fatia 3): the REAL EVENT.ALARM.* wire payload is
// { controller_id, alarm_type, priority, transition, value, limit, timestamp } — it has
// NO alarm_id/state. Treat the WS `alarm` frame as a TRIGGER to refetch GET /alarms/active
// (backend = source of truth); the row type below is the REST row, not the WS payload.
export interface AlarmRow   { alarm_id: string; severity: string; state: string; /* + REST fields */ }  // GET /alarms/active
export interface AiData     { gamma: number; ki: number; strategy: string; }        // ACTION.AI.{id} (pid_worker.py:205)
export interface StatsData  {                                                          // STATS.{id} (stats_worker.py:159)
  iae: number; itae: number; ise: number; mse: number;
  sigma: number; tv: number; var_range: number; var_sp: number;
}
```

> **Wire vs. typed:** payloads are plain msgpack dicts, not the frozen event dataclasses.
> The `StatusData`/`StatsData` fields above are copied from the real publish sites
> (backend map §9, §12). The Fatia 0+1 plan confirms exact dict keys at the publish
> sites and adjusts these interfaces if a key name differs; downstream plans follow.
> **`STATS.{id}` is published on the INTERNAL EventBus** (`stats_worker.py:159`) even
> though the legacy ZMQ `tcp://5555` bridge whitelist skips it — RealtimeWS subscribes
> to the bus DIRECTLY, so `stats` IS available to the web client (Fatia 4/6).

## 5. `useRealtime` hook — `src/realtime/useRealtime.ts` (CANONICAL, Fatia 0+1)

One shared WS connection (opened by `RealtimeProvider`). The hook reads from context.
Coalesced last-value Maps for `status`/`stats`; event subscriptions for discrete
`alarm`/`ai`/system events. Auto-reconnect with exponential backoff; on reconnect it
fires an `onResync` so consumers refetch REST (`controllers`, `alarms/active`, `ai/status`).

```ts
export interface UseRealtime {
  connected: boolean;
  lastStatus: ReadonlyMap<number, StatusData>;   // keyed by loop_id
  lastStats: ReadonlyMap<number, StatsData>;     // keyed by loop_id
  /** Subscribe to discrete (lossless) events. Returns an unsubscribe fn. */
  subscribe<T = unknown>(type: RealtimeType, handler: (env: RealtimeEnvelope<T>) => void): () => void;
  /** Register a callback fired after a reconnect, so the caller can re-sync via REST. */
  onResync(cb: () => void): () => void;
}
export function useRealtime(): UseRealtime;
```

**WS auth = first-message auth** (NOT `?token=`): client opens `/ws/realtime`, sends
`{ "type": "auth", "token": "<JWT>" }` as the first frame; backend validates (reusing
`auth.py`), and **validates the `Origin` header**, else closes with code `4401`.
(Ticket-based auth is an acceptable backend alternative, but the client contract above
is canonical; if the backend chooses tickets, Fatia 0+1 updates this section.)

## 8. GAP register (resolve inside the named fatia plan, with an explicit investigation task)

- **GAP-2a (Fatia 2 — PID params):** there is **no** `POST /commands/pid/params`. Use
  `POST /commands/tuning` (now guardrailed: clamp + admin). Plan must reference the real
  `TuningCommand` body shape from the backend surface map.
- **GAP-2b (Fatia 2 — "enable PID"):** the umbrella mentions an "enable PID" control that
  does **not** exist in `routers/commands`. `POST /commands/optimization` enables the
  **AI optimizer**, not the PID. The Fatia 2 plan MUST start with an investigation task
  that confirms (from the backend code) the real mechanism, and either (a) maps the control
  to `/commands/optimization` if "enable" means the optimizer, or (b) drops/limits the
  control with a noted GAP if no PID-enable endpoint exists. Do NOT invent an endpoint.
- **GAP-4a (Fatia 4 — export listing):** there is **no** `GET /export/list`. The plan must
  confirm the real export-creation + retrieval endpoints from the backend map and either
  use only `GET /export/{export_id}` + `/download`, or note the missing-listing GAP and
  scope export history out. Do NOT invent a listing endpoint.
- **GAP-3a (Fatia 3 — alarm states):** the real `AlarmState` enum has **3** values
  (`UNACK`, `ACK`, `CLEARED_UNACK`) + priorities `CRITICAL/WARNING/ADVISORY/LOG` and types
  `HIHI/HI/LO/LOLO/DV_HI/DV_LO` (backend map §13). The spec's "4-state machine
  (active/ack/cleared-unack/cleared+acked)" maps onto these as: active=`UNACK`, acked-while-active=`ACK`,
  cleared-but-unacked=`CLEARED_UNACK`, and "cleared+acked" = the alarm leaving the active list
  (removed). The plan MUST use the real enum values; do not invent a 4th state.
- **GAP-7a (Fatia 7 — project auth source):** the backend map shows `/project/*` is
  **unauthenticated in the worktree's branch** because the auth fix lives on
  `fix/backend-security-hardening` (not yet merged here). The plan ASSUMES that fix is applied
  (auth + `require_authenticated_admin` on every project route, path sanitization, 413 upload cap)
  and references it as a precondition — it does NOT re-implement it.
- **Fatia 7 RBAC removal:** the spec's "negative RBAC tests (assert 403 by role)" become
  "assert **401** when unauthenticated" (single-admin). Drop the user-management page and
  user CRUD entirely. Keep settings, OPC connection page, `.spid` project management, welcome.

## 9. Global constraints (every task inherits these)

- **Backend:** bind `127.0.0.1` (config `SPID_API_HOST`); serve SPA via
  `app.mount('/', StaticFiles(directory=dist, html=True))` mounted **after** routers
  (single-origin → no CORS in prod); dev CORS allowlist `http://127.0.0.1:5173` only;
  add security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin`, basic CSP). Validate `Origin` on `/ws/realtime`.
- **RealtimeWS:** it is the **2nd EventBus consumer**, structurally analogous to
  `TelemetryPublisher`. The bus `recv()` is **blocking ZMQ** — a naive `await sub.recv()`
  freezes the daemon loop. Use `zmq.asyncio` **or** a single shared consumer in
  `run_in_executor` (single-flight) that fans out to all clients. **Never** a recv-loop
  per client; **never** concurrent recv on the same socket. Coalesce last-value only for
  `status`/`stats`; `alarm`/`ai`/system are **lossless bounded** (on overflow, close the
  socket so the client re-syncs via REST). `ConnectionManager` with async lock + resilient broadcast.
- **TDD (mandatory):** failing test → run it red → minimal impl → run it green → commit.
  Bite-sized steps (2–5 min each), checkbox `- [ ]` syntax.
- **Branching (inviolable):** each fatia is implemented on a **new dedicated branch from
  `main`** (e.g. `feat/web-fatia01-foundation-dashboard`). Never reuse another task's branch,
  never commit to `main` directly, never touch `feat/windows-installers`. Merge to `main`
  only with explicit user approval.
- **Subagents:** `model: opus` (project rule).
- **Commits:** conventional (`feat(web): …`, `fix(web): …`); **no attribution trailers**.
- **Python toolchain:** Python 3.13, `uv`. Lint `uv run --with ruff ruff check .`
  (line-length 100). Types `uv run mypy packages/` (baseline ~540 errors — must not increase).
  Tests `uv run pytest`. uv fallback in Flatpak: `/home/luciano/.var/app/com.visualstudio.code/bin/uv`.
- **Frontend toolchain:** `npm` inside `packages/smart_pid_web/`. `npm run test` (Vitest),
  `npm run test:e2e` (Playwright), `npm run build` (Vite), `npm run gen:api`.
- **Known-environmental:** 3 pre-existing failures in
  `tests/.../test_opcua_endpoint.py::TestProjectServiceOPCUA` (Py3.14 `asyncio.get_event_loop()`)
  are NOT regressions — do not "fix" them inside a fatia.
- **UI specs upkeep:** any UI change updates `docs/smartPIDv2.md` + the relevant
  `docs/identidade_visual_*.md`; this design-system spec is the web UI authority.
- **GateGuard:** the first `Write` of each new file may be blocked by a PreToolUse hook —
  present the facts (no importers yet / no API or schema change / instructed to create) and
  retry the same Write, or the operator may `export ECC_GATEGUARD=off`.
